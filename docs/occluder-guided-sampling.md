Контрольная точка 2.8: Windows, Abandoned Factory, 10/10 кадров,
43 кандидата, 1280 GPU-проб (1239 валидных), MAE 0,04267.
Пакетный GPU-режим подтверждён на малом запуске, не на 600 кадрах.

## 2.9.1 — первый рабочий срез исходного кода

Опция `guided_sampling`: off (по умолчанию) / obstacle.
Требуются AVF и ранее подготовленный кэш умной расстановки 2.7, включая
objects.jsonl. Не требуется повторный скан карты при наличии этих файлов.

Для целей light/moderate/heavy: локальный пространственный индекс
уникальных объектов, выбор потенциальных углов AABB и камеры на дальней
стороне границы; до двух направленных колец с низкими допустимыми высотами,
с сохранением широких ракурсов. Open оставляет исходный банк. Предложения
позиции танка переупорядочиваются по достижимым препятствиям, каждая пятая
позиция сохраняет старый порядок. Ни один предложенный танк не считается
физически допустимым без текущей native проверки.

Python публикует неизменяемый банк ракурсов для каждого кандидата размещения.
Dagor использует банк фактически выбранного placement_candidate, а Python
проверяет индекс и guided_camera_plan; сохраняются выбранные банки в плане
и метаданные guided_sampling. При попадании внутрь целевого диапазона
с запасом от границ возможна досрочная остановка после группы GPU.
Окончательное решение по видимости/COCO — только существующие полные маски.

AABB — грубый приоритет, не доказательство реального перекрытия. Скан 2.7
не гарантирует полноту статической геометрии. Положение камеры внутри
сложных объектов ещё не проверяется точной геометрией. Нативная компиляция
и результат Windows не подтверждены. Добавлены Python-тесты и CI-триггер.

## 2.9.2 — предварительная отбраковка (код реализован)

Новая опция `guided_prerender`: off (по умолчанию) / conservative.
Требуется obstacle. Фильтр не кредитует квоты: он только пропускает
полный рендер. Разрешение на отказ публикует Python для текущей карты
и запроса, если ячейка open насыщена до min(глобальная квота open,
квота карты), open не входит в полезные следующие категории и текущая
цель не open. Каждая пятая попытка карты исключена из фильтра.
Native принимает разрешение только при >=8 валидных пробах,
без невалидных среди выполненных, с минимумом видимости >=98%.
Неизвестные пробы никогда не повод отбрасывать кадр.
Если проверенный полный кадр на карте показывает не-open при AVF>=98%,
фильтр автоматически отключается для этой карты до конца запуска.

Отказ redundant_open_probe записывается в KEFRAME и подтверждается ready
без PNG/масок, учитывается в общем лимите кандидатов и отдельно от
геометрических отказов, ошибок глубины и стабильности. При итоговой
сверке проверяются причина, количество проб, индекс расстановки, цель,
разрешение и отсутствие файлов. Квоты, полные маски и COCO неизменны.
Manifest/visibility-quotas фиксируют guided_prerender_rejections,
guided_prerender_probes и guided_prerender_disabled_maps. В benchmark
добавлен явный флаг --compare-guided для сравнения разных режимов.

Приёмка после реализации этапа: A/B/C — off/off, obstacle/off,
obstacle/conservative с одинаковым seed и всеми остальными настройками.
Сопоставить полный wall time, число дорогих рендеров, число проб с учётом
отказов, точность масок и успешность строгих квот. Фильтр может не
сработать на карте, где open ещё полезен или AVF нестабилен; это штатно.
Тесты Python добавлены, не запущены здесь; Windows сборка и тест не проверены.

## 2.9.3–2.9.4 — фиксированная камера и локальная карта глубины (первый срез)

Опция guided_sampling=fixed_camera добавляет к directed obstacle режиму
локальный предвыбор позиции танка. Для целей light/moderate/heavy Python
выбирает ориентированную на край препятствия камеру и до шести позиций
со смещением вдоль поперечной оси (0, ±2, ±4, -6 м), с сохранением
обычных запасных точек. Соблюдаются границы карты, отступ и диапазон
дистанций. Каждая пятая попытка карты сохраняет прежний способ поиска.
Открытые сцены не меняются. Все локальные точки проходят прежние
native проверки опоры, воды, объёмов RI и статических лучей.

Если валидны минимум две точки, Dagor использует общую камеру и полную
проекцию 256 пикселей по длинной стороне. Независимый экземпляр модели
и копия скелета позволяют не менять основной модельный инстанс.
Синтетический танк не привязан к проходу окружения. Окружение рисуется
и читается один раз, затем каждый изолированный танк в своём положении.
Сравнение reverse-Z: env <= model + tolerance означает видимость;
нулевая глубина окружения означает отсутствие заслоняющей геометрии.
Невалидная или недостаточная проба не получает численной оценки.
Данные глубины существуют только внутри одного вызова; нет повторного
использования между картами, камерами, кадрами или изменениями сцены.
GPU-редукция этой разновидности ещё не реализована: здесь CPU-reference.
Существующий пакетный AVF GPU продолжает работать при финальном поиске.

Выбранная валидная позиция направляется в обычный поиск камеры AVF.
В этом срезе фиксированная камера — предвыбор, не обязательная финальная
камера. При отсутствии валидной оценки используется первая допустимая
точка либо обычный fallback. Полные маски и квоты не изменены.
Метаданные fixed_camera_preselection, FIXED_PRESELECT и benchmark
фиксируют число позиций, валидных проб, проходов окружения и выбранную
оценку. Сводка manifest учитывает измерения полных валидированных кадров,
а native log также содержит предвыбор для отбраковок.

Добавлены Python-тесты групп, reverse-Z и идемпотентных миграций.
Они не запускались в этой среде (git не разрешает DNS github.com).
Сборка C++ Windows и визуальная проверка не выполнены. Следующий срез:
проверенный фиксированный ракурс должен становиться явным кандидатом
финального AVF; затем перенос environment-only сравнения на GPU и
поиск настоящих границ глубины. Не выдавать CPU-предвыбор за готовую
оптимизацию GPU и не сливать в main до приёмки.

### 2.9.3–2.9.5 — сохранение фиксированного ракурса и реальные границы depth

В ветке добавлено продолжение fixed_camera (V2/V3). Если локальная группа
дала валидную оценку, её точные eye и look-at становятся кандидатом 0
обычного AVF; камера повторно измеряется штатной парой depth-проходов
и конкурирует с остальными ракурсами. Если выигрывает другой кандидат,
используется обычный путь. Сдвиг композиции применяется относительно
якоря группы; фактическая позиция модели на экране зависит от её смещения,
поэтому planned screen bin не следует интерпретировать как измеренный.
Полные маски и квоты остаются авторитетными.

Из единственной CPU-копии environment-only depth рассчитывается карта
реальных перепадов: обратный Z переводится в метрическую глубину,
соседняя пара считается границей при разности > max(0,6 м, 6% меньшей
глубины). Для каждого изолированного положения считаются только пары
пикселей внутри силуэта модели, которые лежат на такой границе и
переходят из видимой в закрытую область. Выбор позиции определяется
целевой видимостью, с дополнительным ограниченным бонусом за пересечения
(до 0,015 по оценке). Это первые экспериментальные пороги, не результат
калибровки на датасете.

Добавлены FIXED_DEPTH_EDGES, FIXED_DEPTH_POSE, fixed_group_edge_hits,
fixed_camera_selected, fixed_group_eye/look_at и строгая Python-сверка
фактического ракурса; manifest считает selected_fixed_views. При выборе
fixed camera в записи кандидата публикуются фактические азимут и
горизонтальная дистанция относительно корня модели. Прежний банк камер
остаётся в плане как fallback. Добавлены регрессии обратного Z, границ,
метаданных и миграции прежних версий патчей.

Готовность: это ранжирование уже предложенных и проверенных локальных
позиций по реальной глубине, а не полноценная генерация новых координат
из контуров depth. Обратное проектирование границ в мир, адаптивное
уточнение новых точек, GPU-редукция environment-only, отдельные стратегии
рельефа/растительности/проёмов и накопительный кэш ещё не реализованы.
Сборка Windows и новые Python-тесты здесь не подтверждены (нет DNS
github.com в локальном контейнере; код записан через GitHub).
Не сливать в main до приёмки.
