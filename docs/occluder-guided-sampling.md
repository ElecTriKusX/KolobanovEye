# Этап 2.9 — направленный поиск перекрытий

Контрольная точка 2.8: Windows, Abandoned Factory, 10/10 кадров,
43 кандидата, 1280 GPU-проб (1239 валидных), MAE 0,04267.
Пакетный GPU-режим подтверждён на малом запуске, не на 600 кадрах.

## 2.9.1 — первый рабочий срез исходного кода

Опция `guided_sampling`: off (по умолчанию) / obstacle.
Требуются AVF и ранее подготовленный кэш умной расстановки 2.7, включая
objects.jsonl. Не требуется повторный скан карты при наличии этих файлов.

Для целей light/moderate/heavy: локальный пространственный индекс
уникальных объектов, выбор потенциальных углов AABB и камеры на дальней
стороне границы; до двух направленных колец с низкими допустимыми высотами,
с сохранением широких ракурсов. Open оставляет исходный банк. Предложения
позиции танка переупорядочиваются по достижимым препятствиям, каждая пятая
позиция сохраняет старый порядок. Ни один предложенный танк не считается
физически допустимым без текущей native проверки.

Python публикует неизменяемый банк ракурсов для каждого кандидата размещения.
Dagor использует банк фактически выбранного placement_candidate, а Python
проверяет индекс и guided_camera_plan; сохраняются выбранные банки в плане
и метаданные guided_sampling. При попадании внутрь целевого диапазона
с запасом от границ возможна досрочная остановка после группы GPU.
Окончательное решение по видимости/COCO — только существующие полные маски.

AABB — грубый приоритет, не доказательство реального перекрытия. Скан 2.7
не гарантирует полноту статической геометрии. Положение камеры внутри
сложных объектов ещё не проверяется точной геометрией. Нативная компиляция
и результат Windows не подтверждены. Добавлены Python-тесты и CI-триггер.

## 2.9.2 — предварительная отбраковка (код реализован)

Новая опция `guided_prerender`: off (по умолчанию) / conservative.
Требуется obstacle. Фильтр не кредитует квоты: он только пропускает
полный рендер. Разрешение на отказ публикует Python для текущей карты
и запроса, если ячейка open насыщена до min(глобальная квота open,
квота карты), open не входит в полезные следующие категории и текущая
цель не open. Каждая пятая попытка карты исключена из фильтра.
Native принимает разрешение только при >=8 валидных пробах,
без невалидных среди выполненных, с минимумом видимости >=98%.
Неизвестные пробы никогда не повод отбрасывать кадр.
Если проверенный полный кадр на карте показывает не-open при AVF>=98%,
фильтр автоматически отключается для этой карты до конца запуска.

Отказ redundant_open_probe записывается в KEFRAME и подтверждается ready
без PNG/масок, учитывается в общем лимите кандидатов и отдельно от
геометрических отказов, ошибок глубины и стабильности. При итоговой
сверке проверяются причина, количество проб, индекс расстановки, цель,
разрешение и отсутствие файлов. Квоты, полные маски и COCO неизменны.
Manifest/visibility-quotas фиксируют guided_prerender_rejections,
guided_prerender_probes и guided_prerender_disabled_maps. В benchmark
добавлен явный флаг --compare-guided для сравнения разных режимов.

Приёмка после реализации этапа: A/B/C — off/off, obstacle/off,
obstacle/conservative с одинаковым seed и всеми остальными настройками.
Сопоставить полный wall time, число дорогих рендеров, число проб с учётом
отказов, точность масок и успешность строгих квот. Фильтр может не
сработать на карте, где open ещё полезен или AVF нестабилен; это штатно.
Тесты Python добавлены, не запущены здесь; Windows сборка и тест не проверены.

## 2.9.3–2.9.4 — фиксированная камера и локальная карта глубины (первый срез)

Опция guided_sampling=fixed_camera добавляет к directed obstacle режиму
локальный предвыбор позиции танка. Для целей light/moderate/heavy Python
выбирает ориентированную на край препятствия камеру и до шести позиций
со смещением вдоль поперечной оси (0, ±2, ±4, -6 м), с сохранением
обычных запасных точек. Соблюдаются границы карты, отступ и диапазон
дистанций. Каждая пятая попытка карты сохраняет прежний способ поиска.
Открытые сцены не меняются. Все локальные точки проходят прежние
native проверки опоры, воды, объёмов RI и статических лучей.

Если валидны минимум две точки, Dagor использует общую камеру и полную
проекцию 256 пикселей по длинной стороне. Независимый экземпляр модели
и копия скелета позволяют не менять основной модельный инстанс.
Синтетический танк не привязан к проходу окружения. Окружение рисуется
и читается один раз, затем каждый изолированный танк в своём положении.
Сравнение reverse-Z: env <= model + tolerance означает видимость;
нулевая глубина окружения означает отсутствие заслоняющей геометрии.
Невалидная или недостаточная проба не получает численной оценки.
Данные глубины существуют только внутри одного вызова; нет повторного
использования между картами, камерами, кадрами или изменениями сцены.
GPU-редукция этой разновидности ещё не реализована: здесь CPU-reference.
Существующий пакетный AVF GPU продолжает работать при финальном поиске.

Выбранная валидная позиция направляется в обычный поиск камеры AVF.
В этом срезе фиксированная камера — предвыбор, не обязательная финальная
камера. При отсутствии валидной оценки используется первая допустимая
точка либо обычный fallback. Полные маски и квоты не изменены.
Метаданные fixed_camera_preselection, FIXED_PRESELECT и benchmark
фиксируют число позиций, валидных проб, проходов окружения и выбранную
оценку. Сводка manifest учитывает измерения полных валидированных кадров,
а native log также содержит предвыбор для отбраковок.

Добавлены Python-тесты групп, reverse-Z и идемпотентных миграций.
Они не запускались в этой среде (git не разрешает DNS github.com).
Сборка C++ Windows и визуальная проверка не выполнены. Следующий срез:
проверенный фиксированный ракурс должен становиться явным кандидатом
финального AVF; затем перенос environment-only сравнения на GPU и
поиск настоящих границ глубины. Не выдавать CPU-предвыбор за готовую
оптимизацию GPU и не сливать в main до приёмки.

### 2.9.3–2.9.5 — сохранение фиксированного ракурса и реальные границы depth

В ветке добавлено продолжение fixed_camera (V2/V3). Если локальная группа
дала валидную оценку, её точные eye и look-at становятся кандидатом 0
обычного AVF; камера повторно измеряется штатной парой depth-проходов
и конкурирует с остальными ракурсами. Если выигрывает другой кандидат,
используется обычный путь. Сдвиг композиции применяется относительно
якоря группы; фактическая позиция модели на экране зависит от её смещения,
поэтому planned screen bin не следует интерпретировать как измеренный.
Полные маски и квоты остаются авторитетными.

Из единственной CPU-копии environment-only depth рассчитывается карта
реальных перепадов: обратный Z переводится в метрическую глубину,
соседняя пара считается границей при разности > max(0,6 м, 6% меньшей
глубины). Для каждого изолированного положения считаются только пары
пикселей внутри силуэта модели, которые лежат на такой границе и
переходят из видимой в закрытую область. Выбор позиции определяется
целевой видимостью, с дополнительным ограниченным бонусом за пересечения
(до 0,015 по оценке). Это первые экспериментальные пороги, не результат
калибровки на датасете.

Добавлены FIXED_DEPTH_EDGES, FIXED_DEPTH_POSE, fixed_group_edge_hits,
fixed_camera_selected, fixed_group_eye/look_at и строгая Python-сверка
фактического ракурса; manifest считает selected_fixed_views. При выборе
fixed camera в записи кандидата публикуются фактические азимут и
горизонтальная дистанция относительно корня модели. Прежний банк камер
остаётся в плане как fallback. Добавлены регрессии обратного Z, границ,
метаданных и миграции прежних версий патчей.

Готовность: это ранжирование уже предложенных и проверенных локальных
позиций по реальной глубине, а не полноценная генерация новых координат
из контуров depth. Обратное проектирование границ в мир, адаптивное
уточнение новых точек, GPU-редукция environment-only, отдельные стратегии
рельефа/растительности/проёмов и накопительный кэш ещё не реализованы.
Сборка Windows и новые Python-тесты здесь не подтверждены (нет DNS
github.com в локальном контейнере; код записан через GitHub).
Не сливать в main до приёмки.


### 2.9.5 — обратное проектирование и обратная связь (V4)

Нативный fixed-depth проход использует уже прочитанную карту окружения.
Для каждой валидной изолированной модели вычисляются центр силуэта и
средняя метрическая глубина. Среди настоящих перепадов depth ищется
ближайшая граница, у которой передняя и задняя глубины разделяют
плоскость модели (запас 0,5 м с обеих сторон). Граница проектируется
на плоскость средней глубины модели, затем в мировые координаты через
базис камеры. Это гипотеза положения, не точная 3D-точка поверхности.
Горизонтальное смещение относительно центра ограничено 0,5–8 м;
до шести предложений с дедупликацией 1 м. При невалидном предвыборе
предложения не публикуются.

Python проверяет fixed_world_edge_count и координаты, фильтрует
отступы карты, дистанцию камеры, радиус 14 м от исходного якоря.
Очередь ограничена 32 предложениями на карту, дедупликация по 2-метровым
ячейкам, привязка к карте и запрошенной квоте. На последующей попытке
fixed_camera использует исходное положение камеры и новый локальный
банк (0, ±1, ±2,5, -4 м); очередная экранная композиция может менять
направление камеры. Не более одного использования каждой гипотезы;
нет рекурсивной цепочки feedback. Обычные запасные точки сохранены.
Новые позиции проходят прежние проверки рельефа, воды, коллизий,
AVF и полные маски. Пропуски RGB не дают квотного кредита.
Обратная связь пополняется только из валидированных полных кадров
(не обязательно принятых в квоты), без сохранения между запусками.

В manifest.fixed_camera добавлены world_edge_proposals,
depth_feedback_offered и depth_feedback_used. Добавлены четыре
регрессионных теста (проекция, протокол, очередь, миграция).
Пороги экспериментальные. Новые Python-тесты и Windows-сборка
не подтверждены. Следующие задачи: специализированные предложения
рельефа/растительности/проёмов, устойчивый кэш, GPU environment-only
и комплексный тест. Main и рабочая ветка AVF не изменены.


### 2.9.6 — специализированные семейства сцен (экспериментальный код)

Новый опциональный guided_sampling=diverse; старые режимы сохранены.
По каждой карте только для запросов light/moderate/heavy циклически
выбираются building, vegetation, aperture, terrain, explore. Open
оставляет широкий поиск. При отсутствии локальной геометрии для
запрошенного семейства используется fallback, а не фиктивная метка.
Семейства являются происхождением предложения, не ground truth
типа перекрытия. Квоты видимости и COCO не меняются.

Building использует индекс построек, камней и малых объектов;
vegetation — отдельный индекс растительности и более низкий профиль
высоты камеры. Aperture ориентируется на потенциальные руины, ангары,
ворота и другие ресурсы с именами-признаками, предлагает направления
к внутренней части габаритов и краям; при наличии обратной связи depth
используется её отдельное семейство. Никаких изменений геометрии карты.

Для terrain используется широкий банк низких ракурсов. Native запрашивает
11 точек высотного профиля между камерой и моделью и оценочно
проецирует верхнюю границу рельефа на вертикальный габарит модели.
По этой оценке меняется только порядок до четырёх первых AVF-проб
(чередование с обычным поиском). Неизвестный рельеф не считается
перекрытием; окончательная оценка только по рендеру.

V5 fixed-depth: подсчитываются строки и столбцы, где непрерывный
видимый участок изолированной модели длиной >=2 пикселей ограничен
закрытыми участками и реальными перепадами глубины с обеих сторон.
Для aperture эта топология даёт небольшой бонус <=0,025 при предвыборе
позиции. Это свидетельство двухстороннего перекрытия, но не доказательство
наличия окна/двери; растительность и промежутки тоже могут его создавать.
Полные маски остаются обязательными.

scene_families в manifest и benchmark: попытки, валидированные полные
кадры, совпадения с целевым диапазоном, попытки увеличения квотного
результата, фактические диапазоны. В метаданных кандидата отдельно
requested и proposal, is_ground_truth=false. fixed_group_aperture_hits
и aperture_witness_groups фиксируют свидетельства топологии. Добавлены
семь тестов и миграции V5. Тесты и Windows-сборка не запускались здесь;
локальный checkout недоступен из-за DNS. Пороги и распределение
семейств экспериментальные. Следом 2.9.7 — постоянный кэш,
GPU environment-only и комплексная проверка остаются незавершёнными.


### 2.9.7 — накопительный кэш сцен (опциональный код)

Настройка scene_cache — пустая строка (выкл.) либо отдельная папка,
общая для разных запусков. GUI: «Кэш интересных сцен (2.9.7)».
Работает в fixed_camera и diverse. База scene-hints.sqlite3 находится
вне каталогов игры, Dagor и текущего запуска.

Область совместимости: SHA-256 файла карты, GRP модели, objects.jsonl
и отпечаток исходного инвентаря 2.7, имена модели/скелета, основные
параметры размещения и камеры, версия формата. Seed и выходной каталог
не входят в ключ. Это не хеш всех ресурсов игры/шейдеров, поэтому
повторная проверка кадра обязательна и после обновления окружения.

Обучение: только полная валидированная маска с совпадением целевой
light/moderate/heavy и реально выбранной фиксированной камерой, локальная
позиция из группы. Сохраняется представитель на ячейку 32 м и целевой
диапазон. Наблюдения новой сцены в той же ячейке не увеличивают счётчик
успеха старой записи. Сохранение транзакционное, только после финальной
сверки native-журнала и согласия планировщика с полным пулом; допускается
неполный набор квот, если аудит прошёл. Аварийный запуск до аудита не
обновляет историю. Ошибка записи кэша сообщается отдельно, не ломает
валидный экспорт; ошибка открытия сообщается как ошибка запуска.

Повтор: максимум один запрос кэша на шесть не-open запросов карты,
не заменяет explore в diverse, одна пространственная ячейка на карту
за запуск. Загруженные в начале подсказки используются без рекурсивного
самообучения. Банк содержит новые поперечные смещения ±1,5, ±3, ±5 м,
обычные запасные точки и прежние проверки. Не гарантия отсутствия
визуальных дубликатов вне кэша; для контроля всего датасета потребуется
отдельная метрика сходства. Успех повтора — полная маска целевого класса
и выбранный фиксированный ракурс с локальной точкой. Другой измеренный
результат — промах; техническая/предварительная отбраковка без полной
маски учитывается как unmeasured, не штрафует оценку. Приоритет по
(hits+1)/(hits+misses+2), затем меньшему uses, стабильной сортировке.
Лимит 512 записей на scope; старые несовместимые scope сохраняются,
их можно убрать удалением отдельной базы при остановленных генераторах.

В manifest/visibility-quotas и benchmark включён scene_cache:
loaded, replays, hits, misses, unmeasured_rejections,
learned_observations, inserted_hints, committed. План содержит ключ
повтора; валидированный кадр содержит происхождение, не ground truth.
Для A/B сравнения использовать --compare-guided и отдельно пустую базу
и прогретую базу. Пять тестов Python добавлены. Windows не проверен.

### 2.9.4 — GPU environment-only reduction (V6)

Реализован отдельный DX11 compute shader engine/shaders/ke_fixed_reduce.hlsl,
который компилируется fxc в общий статический заголовок вместе с обычным
AVF. Используется одна неизменяемая D32-текстура окружения и независимая
D32-текстура модели, очищаемая перед каждым изолированным положением.
Группа до 6 положений: GPU dispatch всех доступных позиций перед сбором
результатов. У каждого положения свой unmanaged BufPtr и event query.
Ресурсы ограничены временем группы; между группами depth не сохраняется.

Новый редуктор сравнивает environment-only reverse-Z (нулевая глубина
окружения допустима), считает amodal/visible/invalid, пересечения реальных
depth-границ, aperture scanlines, суммы координат/габариты силуэта и
групповые суммы метрической глубины. Буфер 12 uint32 + одна float-сумма
на workgroup 8x8, с проверкой числа завершённых workgroups и диапазонов.
Проекция фиксированная симметричная, near=.2, far=20000; остальные
параметры этого прохода не поддерживаются. CPU получает ровно одну
полную карту окружения на успешную группу, сохраняет вычисление карты
границ и обратное проектирование. GPU-only не читает полные model-depth
текстуры. Финальный AVF, RGB, полные маски и квотная проверка неизменны.

При 256x144 и шести отрисованных позициях номинальный объём чтения
с CPU: 7*147456 = 1032192 B; GPU: 147456 + 6*(12+576)*4 = 161568 B
(на 84.35% меньше полезных данных readback, без padding/driver overhead).
Это теоретический объём, не измеренное ускорение. GPU вычисление
топологии и создание ресурсов группы также имеют стоимость.

Режимы наследуются из avf_backend: cpu — эталон; gpu — пакетный редуктор;
verify — GPU и CPU по тем же текстурам, точное сравнение счётчиков,
координат и габаритов, допуск сумм глубины max(0.001, 1e-5*sum).
При расхождении или отказе renderer в verify запуск прерывается;
в gpu ошибка предвыбора приводит к существующему fallback без
валидной оценки. Метаданные backend/submitted/verified сверяются
с планом и количеством размещений. Native benchmark:
FIXED_GPU_GROUP, FIXED_GPU_VERIFY_OK/FAIL, FIXED_GPU_FALLBACK, число
полных model/environment readbacks для успешных групп.

Добавлены пять регрессионных тестов (миграция V5/V6, групповой readback,
capture patch, метаданные, контракт HLSL). Статическая проверка
сборки шаблона C++ из точных GitHub-литералов: все 5 замен V6 найдены,
один renderGeomOpaque, один read(sceneTex), сбалансированные скобки,
dispatch до map результата. Это не компиляция C++/HLSL и не unittest.
Полный checkout в Linux по-прежнему не доступен из-за DNS github.com;
Windows SDK/GPU недоступны. Следующий этап 2.9.8: ревизия патчей,
python -m unittest discover -v, сборка с fxc, smoke в verify, затем
сопоставимые CPU/GPU и разнообразные режимы, 10/100/600 кадров.
Main и рабочая ветка AVF не изменены.
