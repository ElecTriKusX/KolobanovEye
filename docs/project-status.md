Основание: «KolobanovEye 2.0 — техническое задание для Codex», разделы 1–15. Базовая ветка `annotation-generator` включает PR #2 с адаптивным прогревом. Подтверждение Windows для 40 кадров относится к `fix/resolve-white-haze`. Позы Tiger H1 проверены на Windows в PR #3. Лог от 17 ноября 2026 фиксирует успешную сборку Dagor с ooz и шесть кадров с разными углами при seed 42. Валидатор, аудит рельефа, экспорт COCO и создание шести превью завершились успешно. Пользователь подтвердил корректность изображений. Повтор полного набора Python-тестов на Windows после исправления подготовки CRLF-фикстуры ожидается.

## Единый сырой датасет и реорганизация репозитория — 18 ноября 2026

- Пользователь утвердил **один несегментированный `KolobanovEye/dataset/raw` за запуск**, с отдельным этапом работы над разбиением в будущем. Никаких train/val/test или директорий публичных релизов сейчас не создаём.
- **Реализовано в ветке:** `ke_dataset.py` после `ke_multi_generate.py` собирает `raw/images`, `raw/annotations/instances.json` (единый COCO), `raw/metadata/{images.jsonl,scenes.jsonl,maps.json,generation_config.json}`, `raw/manifest.json`. Все файлы исходных кадров привязаны к JSON без необходимости устанавливать Dagor.
- `raw` заменяется целиком **только после успешного рендера, проверки и упаковки**; при ошибке остаётся предыдущая версия. Если `raw` существует, GUI спрашивает разрешение; для CLI нужен `--replace-raw`. `dataset/runs/` хранит техническую диагностику и не удаляется автоматически.
- `.gitignore` запрещает добавлять результат генерации в репозиторий, кроме `dataset/README.md`.
- **Реорганизация исходников:** все Dagor-патчи перенесены в `engine/patches/`, Python-тесты — в `tests/`. Обычные команды запуска оставлены в корне. Схема в `docs/project-layout.md`.
- **Исправление конкретного сбоя сборки:** `dagor-tank-map-bounds.patch` больше не содержит хрупкого фрагмента `strmlevel.h`. `ensure_level_settings_accessor` в `kolobanoveye.py` добавляет геттер по уникальному члену `lmeshMgr`, с сохранением CRLF/LF и идемпотентностью; отдельный Python-тест проверяет эту ситуацию. **На целевом Windows повторная сборка пока не подтверждена**, возможны следующие ошибки компиляции.
- GitHub Actions проверяет синтаксис Python, полную unittest-серию и применимость независимого патча рендера танкового квадрата к закреплённой ревизии Dagor. Реальная DX11-проверка остаётся обязательной.

## Сборка Dagor / OOZ и структура вторичных утилит — 18 ноября 2026

- По приложенному пользователем архиву `build-logs (2).zip` установлена точная причина падения Jam: `strmLevel.cpp(1103,1107,1108)`, `no member named 'getTex2D' in 'resptr_detail::ResFactory<BaseTexture>'`. Декодер `ke-ooz.lib` уже собрался успешно, ошибок OOZ-компиляции нет.
- Исправлено: новая версия `engine/patches/dagor-tank-map-render.patch` объявляет объект целевого текстурного рендера как `UniqueTex target`, а не `auto target`. Функция `upgrade_roi_unique_tex()` в `kolobanoveye.py` обновляет ровно одну декларацию в **уже пропатченном** Dagor без `git reset`; повторное применение идемпотентно.
- OOZ закреплён для **локального** использования в `vendor/ooz/` через `python -m tools.vendor_ooz`. Источник — пять уже скомпилированных decode-only файлов `build-logs/ooz-local`, SHA-256 — `vendor/ooz.lock.json`, исходный коммит `05038060aa68f9187ae9923b2388ca8db40e58d1`. `build` без `--ooz` умеет автоматически использовать такую копию.
- Важно: ясной публичной лицензии на распространение upstream powzix/ooz пока не установлено, поэтому его исходники **не** добавлялись в открытый GitHub; `vendor/ooz/` находится в `.gitignore`. Документация `vendor/README.md`.
- Вторичные Python-модули и CLI (например, `ke_maps`, `ke_validate`, `ke_coco`, `ke_review`, `ke_diagnose`, `ke_recover`) перенесены из корня в `tools/`. Вызывать их теперь `python -m tools.ke_maps` и т. д. Все внутренние импорты, тесты и команды GUI обновлены. В корне оставлены пять основных скриптов.
- GitHub Actions проверяет Python-тесты, команды модулей и применение патча Dagor к закреплённым исходникам. Реальная **повторная сборка Windows/Clang после исправления UniqueTex пока не подтверждена**, поэтому возможны новые ошибки C++ после продолжения сборки.
