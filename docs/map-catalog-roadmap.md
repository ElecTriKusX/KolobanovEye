# KolobanovEye 2.0 — каталог карт и танковое поле

Статус на 2026-11-18. Ветка: `feature/avg-map-catalog-whitelist`, создана от `main`.

> **Актуальное расположение результата:** одна сырая коллекция `dataset/raw/` внутри проекта, технические запуски — `dataset/runs/`. Подробности в `dataset/README.md` и `docs/project-layout.md`. Папки train/val/test и релизов на данном этапе **не реализуем**.

## Зафиксированные решения

- Ищем **только** файлы `<WarThunder>/levels/avg_*.bin` (не рекурсивно). Результаты сортируются по имени, чтобы выбор первой карты и квоты воспроизводились.
- Отображаем все обнаруженные карты и их состояние чтения, но **наличие заголовка DBLD3x64 не доказывает совместимость с Dagor**.
- GUI автоматически сканирует папку при запуске; whitelist хранится **локально**, не в Git. По умолчанию выбирается Normandy, если найдена, иначе первая карта с корректным заголовком. Пустой ручной выбор разрешён и не заменяется автоматически.
- Для размеров танкового поля единственный выбранный источник — **`tankMapCoord0` / `tankMapCoord1` из реального `levelSettingsBlk`**, который Dagor загрузил для данной карты. Не используем миссии, точки появления и NavMesh для границ.
- Если координаты образуют прямоугольник, максимальный вписанный квадрат имеет сторону `min(dx, dz)`; не выходим за исходные границы. Его размещение детерминированно (центр).
- Для обзорной карты **только отдельный offscreen-рендер танкового квадрата средствами Dagor** с вызовом `render_last_clip_in_box` и сохранением PNG; не используем готовые текстуры и кроп полного last_clip.
- Рабочий штатный last_clip и цепочка рендера RGB остаются неизменны; отдельный вспомогательный render target должен восстанавливать GPU-состояние и не влиять на обычные кадры.
- Квоты успешных кадров равномерны по whitelist в сортированном порядке: `q = count // N`, первые `count % N` карт получают по `q+1`. Неиспользуемые карты получают 0; ошибки рендера не считаются кадрами.

## Реализованная архитектура и критерии

1. **Каталог и whitelist.** `tools/ke_maps.py` обнаруживает `levels/avg_*.bin` без доступа к ресурсам игры на запись. GUI показывает найденные карты, недоступные отмечает отдельно, выбор сохраняется в локальном `map-whitelist.local.json`.
2. **Режим tank-area.** Источник границ — только `tankMapCoord0/1` в `AcesScene.levelSettingsBlk`. Для рендера и размещения используется вписанный квадрат; попытки размещения проверяются по heightmap, порогу перепада и высоте земли. Переход на всю карту в GUI отключён.
3. **Один DaEditor для всех выбранных карт.** `ke_single_editor.py` рассчитывает равные квоты с сортировкой по ID. Для каждой карты генерирует BLK и план камер/расстановок. **Один процесс** `daEditor3x-dev.exe` получает один `probe.dcmd` со всеми заданиями `kolobanoveye.frame`, выполняет их последовательно. По завершении карты `AcesScene::loadLevel` загружает следующую, освобождая ресурсы прошлой сцены. Сохранён режим повторной стабилизации RGB перед каждым кадром.
4. **Изоляция ресурсов.** Применяемая сборщиком миграция C++ очищает `levelSettingsBlk` при смене карты, не позволяет потерять `lmeshRenderer` до освобождения предыдущего уровня, а обзорную текстуру сохраняет индивидуально в `runs/<run-id>/maps`. Это реализовано, но **не проверено на Windows DX11**.
5. **Неповторяющиеся выходные данные.** Изображения сразу пишутся во временный `raw/images`. В `dataset/runs/run-...` один набор файлов редактора, `capture/` и `plans/` по картам, общий лог и обзорные карты. Отсутствуют `runs/<map>`, вложенные `runs/`, повторные изображения и второй COCO. После успеха общий `raw/annotations/instances.json` собирается из кадровых журналов.
6. **Анализ по запросу.** Кнопка «Провести анализ» отдельно создаёт `dataset/analysis/index.html`, HTML-карты с точками расстановок и `report.json`. Проверка ориентации X/Z ещё нужна.
7. **Ошибки и приёмка.** Пустой выбор карт запрещён. Если любая карта не завершилась или кадр повреждён, новый `raw` не публикуется и старый остаётся. Технический run сохраняется для диагностики. В тестах моделируется один вызов DaEditor для двух карт и N кадров; реальный Windows-тест является обязательным до слияния.

## Проверка на Windows

```powershell
cd D:\Projects\KolobanovEye
git fetch origin
git switch feature/avg-map-catalog-whitelist
git pull --ff-only origin feature/avg-map-catalog-whitelist
python -m unittest discover -v
python .\kolobanoveye.py build --dagor D:\Projects\DagorEngine
python .\ke_gui.py
```

Начальный контроль: **1 карта, 2 кадра**. Проверить `dataset/raw/images`, `dataset/raw/annotations/instances.json`, `dataset/runs/run-.../maps/avg_normandy.bin-tank.png`. Далее выбрать две совместимые карты и 4 кадра; требовать `MAP_BEGIN`/ `MAP_OK` и `SEQUENCE_OK` **дважды в одном общем логе**, а не два запуска редактора. В `probe.dcmd` должно быть две команды `kolobanoveye.frame` и одна команда `exit no`.

Затем нажать «Провести анализ» и сверить точки с реальными позициями на обеих обзорных текстурах. Если сборка, карта либо RGB не прошли, сохраняем лог, не переключаем `main`.

## Ограничения

- Автоматический scanner не подтверждает, что произвольная `avg_*.bin` совместима с текущей сборкой Dagor: истинный статус зависит от успешного загрузчика и фактического RGB.
- За пределами `tankMapCoord0/1` не ищем границы миссий и NavMesh, как согласовано. Квадрат максимален по этим настройкам; проходимость каждой точки по-прежнему проверяется отдельно.
- Граница в координатах не гарантирует отсутствие воды, зданий, уклонов или что камера останется внутри квадрата при съёмке с краёв; это более глубокие геометрические проверки.
- Текущий `minimum_ground_y=0.5` исторически подбирался для Normandy, для остальных карт может требоваться корректировка; индивидуальные профили условий не реализованы.
- `render_last_clip_in_box` рисует прежде всего рельеф и декали, не гарантирует спутниковую RGB-карту со всеми зданиями.
- После ошибки на очередной карте генерация останавливается, сохраняет технический `runs/<run-id>/manifest.json` и прежний `raw`; автоматический повтор и перераспределение неуспешных кадров ещё отсутствуют.
