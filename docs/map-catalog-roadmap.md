# KolobanovEye 2.0 — каталог карт и танковое поле

Статус на 2026-11-18. Ветка: `feature/avg-map-catalog-whitelist`, создана от `main`.

## Зафиксированные решения

- Ищем **только** файлы `<WarThunder>/levels/avg_*.bin` (не рекурсивно). Результаты сортируются по имени, чтобы выбор первой карты и квоты воспроизводились.
- Отображаем все обнаруженные карты и их состояние чтения, но **наличие заголовка DBLD3x64 не доказывает совместимость с Dagor**.
- GUI автоматически сканирует папку при запуске; whitelist хранится **локально**, не в Git. По умолчанию выбирается Normandy, если найдена, иначе первая карта с корректным заголовком. Пустой ручной выбор разрешён и не заменяется автоматически.
- Для размеров танкового поля единственный выбранный источник — **`tankMapCoord0` / `tankMapCoord1` из реального `levelSettingsBlk`**, который Dagor загрузил для данной карты. Не используем миссии, точки появления и NavMesh для границ.
- Если координаты образуют прямоугольник, максимальный вписанный квадрат имеет сторону `min(dx, dz)`; не выходим за исходные границы. Его размещение детерминированно (центр).
- Для обзорной карты **только отдельный offscreen-рендер танкового квадрата средствами Dagor** с вызовом `render_last_clip_in_box` и сохранением PNG; не используем готовые текстуры и кроп полного last_clip.
- Рабочий штатный last_clip и цепочка рендера RGB остаются неизменны; отдельный вспомогательный render target должен восстанавливать GPU-состояние и не влиять на обычные кадры.
- Квоты успешных кадров равномерны по whitelist в сортированном порядке: `q = count // N`, первые `count % N` карт получают по `q+1`. Неиспользуемые карты получают 0; ошибки рендера не считаются кадрами.

## Этапы и критерии

### 1. Каталог и обнаружение (лёгкий Python, без Dagor)
**План:** `ke_maps.py`: найти уровни, проверить заголовки, вернуть ID, имя, размер, статус и диагностические ошибки. Не читать и не менять файлы игры.
**Приёмка:** в GUI и CLI одинаково отсортированный список `avg_*.bin`; неизвестные/битые файлы отмечены, а не превращаются в доступные.

### 2. Whitelist + GUI
**План:** окно со списком карт и галочками; автоматическое сканирование при запуске `python ke_gui.py`, повторное сканирование при смене папки игры, сохранение в `map-whitelist.local.json`. Учитывать устаревшие файлы, нулевой выбор, доступность. `main` и работающий генератор пока не трогать.
**Приёмка:** закрытие/открытие GUI сохраняет выбор; при другом каталоге обнаруженные карты обновляются; недоступные карты не попадают в запуск. До реализации этапов 3–7 генерация других карт **не объявляется поддерживаемой**.

### 3. Параметризация загрузки и одиночная карта
**План:** безопасно заменить жестко заданную `LEVEL` на `--level` и config `map_id`, использовать выбранный локальный файл, согласовать `inspect`, cache, карты и выходные метаданные. Прогонять каждый неизвестный уровень в отдельном DaEditor3X, так как `loadLevel` может вызвать fatal.
**Приёмка:** Normandy без регрессии; ещё одна `avg` карта реально загружена и дала RGB, ошибки не ломают цикл.

### 4. Границы танкового поля
**План:** экспорт из Dagor `tankMapCoord0/1` с проверкой существования, конечности, порядка координат, площади, пересечения с высотной картой; только прямоугольник/максимальный вписанный квадрат. Разделить `landscape_bounds`, `tank_rect`, `tank_square`, записывать источник/версию.
**Приёмка:** Normandy из локального файла даёт (0,0) — (4096,4096), сопоставление с доступной игровой конфигурацией. Не подменять недостающие координаты (0,0).

### 5. Ограничение планировщика размещения
**План:** новый `placement_mode=tank_map`, равномерная детерминированная выборка по танковому квадрату; проверки существующей heightmap/воды/уклона остаются включёнными. Квадрат максимален, без глобального отступа 15%; тонкие защитные расстояния рассчитываются по габаритам танка при проверке кандидата.
**Приёмка:** все успешные `tank_world.xz` попадают в границы, при отказах ограниченное число повторов; проверка распределения координат.

### 6. Обзорная текстура танкового поля
**План:** отдельный GPU-рендер в указанный `tank_square`, не захватывать полный landmesh; целевой PNG высокого разрешения (сначала 1024, затем 4096). Использовать `render_last_clip_in_box` и контроль матрицы world→image. Учесть что last_clip — цвет земли/декали, не полный RGB со всеми зданиями.
**Приёмка:** картинка совпадает по координатам с дорогами/рельефом в сцене, нет переворота Z; PNG не пустой, нужный квадрат полностью представлен; обычный RGB не изменился.

### 7. Равные квоты между картами
**План:** вычислить квоты по **отсортированному whitelist**, группировать работу по карте, поначалу отдельный DaEditor3X-процесс на карту. Успешные кадры считать отдельно от попыток. 3/5→1,1,1,0,0 и 7/3→3,2,2.
**Приёмка:** тесты квот, повторяемость при одинаковом seed, метаданные с `map_id`, отсутствие смешения ID и кадров.

### 8. Интеграция / проверка
**План:** объединить результаты COCO с явным `map_id`, учесть split по картам/пространственным участкам, проверить уникальность путей, кэш по уровню+версии+границам+разрешению. Реальные Windows-тесты на нескольких картах, тест прогрева и возобновления.
**Приёмка:** полный набор ожидаемого числа успешных изображений, воспроизводимые конфиги/логи/COCO, контроль RGB и погрешностей bbox.

## Состояние исполнения (18 ноября 2026)

- **Этапы 1–2 подтверждены пользователем на Windows**: автообнаружение, whitelist в GUI и новые тесты работают.
- **Этап 3 — реализован, ожидает Windows-приёмки**: `ke_generate` и GUI передают `map_id` в `kolobanoveye.py --level`; заменяется путь в `capture.blk`, инвентаризация выбранного файла, `plan.json`, метаданные последовательности и ключ кэша старого last_clip. В GUI пока **одна активная карта за запуск**.
- **Этап 4 — реализован, ожидает Windows-приёмки**: новый Dagor-патч `dagor-tank-map-bounds.patch` получает `tankMapCoord0/1` из загруженного `AcesScene.levelSettingsBlk`, пишет `tank_map_min/max` в метаданные, Python экспортирует `tank-map-bounds.json` с `tank_rect`, максимальным вписанным `tank_square` и честным статусом отсутствия.
- **Этап 5 — экспериментально реализован, ожидает Windows-приёмки**: `placement_mode=tank_map` использует нормализованные кандидаты внутри максимального вписанного квадрата, не меняя прежние режимы. Камера у края может выходить за пределы танкового квадрата: это ограничение пока сохраняется.
- **Этапы 6–8 не реализованы**: прямой рендер танкового квадрата, распределение квот между картами и общий многокартовый запуск пока отсутствуют. Старый `capture_last_clip` — отключённая по умолчанию диагностика **всего ландшафта**, не новая обзорная карта.

### Windows-проверки этапов 3–5

1. Запустить `python -m unittest discover -v`.
2. Запустить `python kolobanoveye.py build --dagor D:\Projects\DagorEngine --ooz D:\Projects\ooz`. При ошибке `git apply` сохранить вывод полностью.
3. Проверить `inspect --level levels/avg_normandy.bin`, затем другую `avg_*` карту.
4. В GUI выбрать Normandy, режим «Танковое поле», отступ `0`, 2–3 кадра. Проверить `tank-map-bounds.json` и COCO/RGB. Для Normandy ожидается (0,0)–(4096,4096), если её актуальные настройки соответствуют опубликованным.
5. Повторить другую `avg_*` карту в отдельной серии, проверить `[KE] TANK_BOUNDS`, `[KE] MAP_BOUNDS`, RGB и `map_id` в каждом кадре.
6. При сбое не считать карту поддерживаемой: сохранить `host-stdout.log`, `probe.dcmd.log`, `probe.dcmd.err` и `tank-map-bounds.json` (если появился).
