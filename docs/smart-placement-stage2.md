# 2.7 — инвентаризация объектов и пространственный индекс

Ветка feature/smart-placement. 2.6.b слит по решению пользователя на
промежуточном результате 194/200; завершение Windows-приёмки не подтверждено.

Диагностический запуск «Анализ объектов» в GUI использует выбранные карты,
один DaEditor, существующие границы tank square. CLI:
`python -m tools.ke_objects --dagor D:\Projects\DagorEngine --game D:\Games\WarThunder --output dataset --map levels/avg_finland.bin`.

Выход: dataset/object-analysis/<run>/<map>/. objects-native.tsv (сырой журнал
с заголовком, тайлами и END), objects.jsonl (корень, world AABB, имя, слой,
пул, источник, наличие ресурса коллизии), objects-map.png, density-map.png,
groups-map.png, spatial-index.json, objects-report.json. Оригинальные обзорные
текстуры — maps/. dataset/raw не изменяется.

Сканирование по тайлам <=128 м с ожиданием подготовки RI; владение по
корневой позиции исключает дубли между тайлами. Геометрический обход
обычных RI без обращения к отсутствующим игровым props, отдельно RIExtra
через валидные handle каждого пула, включая без коллизии. Полнота стриминга
пока не доказана; пустой тайл не означает отсутствие геометрии. Статическая
геометрия SCol/FRT пока не перечисляется; деревья/дома по имени ресурса —
эвристика, не классы ML. 16 м ячейки, плотность по корням (логарифмическая
шкала на карту), группы — 8-связные занятые ячейки AABB. Границы AABB
консервативны, не точный контур коллизии. Без обзорной текстуры — явный
однотонный фон и отметка в отчёте. Никакого RGB/масок танка.

До Windows-проверки не подключать к выбору позиций. Следующие шаги 2.7:
доказать покрытие RI и дополнить статическую сцену, проверять объём танка,
подбирать позиции около объектов и затем оценивать видимость.
