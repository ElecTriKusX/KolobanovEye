# Этап 2: экранная композиция и перекрытия

## Реализовано в feature/visibility-quotas

- План экранных положений: 15% center, 65% offset, 15% edge, 5% near_clip.
  Это запланированные положения, а не гарантия фактического отсечения.
- Dagor корректирует направление взгляда без сдвига позиции камеры/танка;
  journal содержит запланированные UV и категорию.
- Экспериментальный режим `capture_visibility_masks` (по умолчанию false).
  Нативный установщик фиксирует LOD на время RGB и изолированного прохода,
  сохраняет действительные параметры финального screenshot, копирует
  reverse-Z глубину сцены до изолированного прохода и вызывает
  `renderIsolated` только для модели танка.
- Сохраняет две бинарные RGB PNG: `raw/masks/amodal/<id>.png` и
  `raw/masks/visible/<id>.png`. Python проверяет размеры, бинарность,
  вложенность видимой маски, подсчёты пикселей и долю видимости.
- В COCO экспериментального режима bbox по видимой непрозрачной части;
  полностью скрытый танк не получает положительной аннотации. Исходный
  приблизительный AABB остаётся в images.jsonl. Сильные перекрытия
  помечены training_eligible=false; весь режим пока diagnostic_only.
- Manifest содержит фактическое распределение измеренной видимости.

## Ограничения / ещё не выполнено

- Native C++: 200/200 RGB и 200 пар масок на 20 картах; пользователь подтвердил визуальную корректность масок.
- Маски описывают глубину непрозрачной геометрии; прозрачность, дым и
  эффекты после G-buffer не покрываются. Доля видимости измеряется только
  для изолированного силуэта внутри кадра. Для отсечения нужен
  отдельный overscan-проход. `frame_fraction` пока null.
- Реализован строгий глобальный отбор по измеренным маскам из конечного пула кандидатов. Адаптивный добор в процессе рендера ещё не реализован.
- Отдельная нарезка full RGB на 640/960 с сохранением группы сцен позже.

## Проверка на Windows

1. `git switch feature/visibility-quotas`, `git pull`.
2. `python -m unittest discover -v`.
3. `python .\kolobanoveye.py build --dagor D:\Projects\DagorEngine`.
4. В GUI включить «Маски видимости (эксперимент)» в меню параметров
   или выставить `"capture_visibility_masks": true` в JSON.
5. Сгенерировать небольшую серию на одной карте и проверить RGB/маски.
   Искать `[KE] VISIBILITY_OK` и `[KE] VISIBILITY_FAIL` в журнале.
6. Проверить открытый танк, частично закрытый зданием/растительностью,
   полностью скрытый, близко к границе. Не обучать на диагностических
   данных до проверки соответствия RGB и масок.

При выключенных масках сохраняется прежний approximate_amodal.

## Строгие квоты: первый рабочий вариант

- `enforce_visibility_quotas=true` требует `capture_visibility_masks=true`.
- `count` — целевое число принятых кадров; `visibility_weights` по умолчанию open/light/moderate/heavy = 40/25/25/10. Округление методом наибольших остатков.
- `visibility_candidate_multiplier` (1–20, default 5): кандидаты распределяются по картам, не более 1000 на карту. Один DaEditor, без повторных запусков. Все кандидаты проверяются до отбора.
- Строгий отбор глобальный; разнообразие карт поддерживается по возможности, но точное равенство карт не гарантируется. Отбор детерминирован, редкие категории имеют приоритет.
- Видимость <10% исключается из этого режима. При недостатке любой категории старый raw сохраняется, кандидаты и журнал сохраняются, отчёт `runs/<run>/visibility-quotas.json` показывает дефицит. При успехе остаются только выбранные RGB/маски/COCO и метаданные; ID могут иметь пропуски.
- Режим без квот сохраняет диагностическое поведение. Адаптивный поиск перекрытий, ранняя остановка рендера, добор по дефициту и фактическое clipping ещё открыты. Windows-проверка квот необходима.
