## Адаптивный добор: эталон планировщика (2.6)

Добавлен `tools/ke_adaptive_quotas.py`: автономный online-планировщик.
Выбор следующей карты/целевой корзины использует остаточную сеть максимального
потока: приоритет получают ячейки, увеличивающие число совместимо отбираемых
кадров, включая обмен уже выбранных кадров. Сглаженная статистика попаданий
по паре карта/запрошенная видимость учитывает промахи proxy. Загруженная карта
предпочтительна при близкой ожидаемой полезности. Один запрос в работе, лимит
попыток по каждой карте, ранняя остановка при точном решении, явный INCOMPLETE
при исчерпании бюджета. Кандидат зачитывается только после валидации; счётчик
выбранных кадров предварительный до публикации. Альтернативные ячейки
сохраняются, число кандидатов на ячейку ограничено её предельной вместимостью.

Планировщик подключён к нативному циклу в 2.6.b. 2.6.a сохранён как отдельный
режим добора целыми пакетами; см. ниже. Маски и строгие квоты остаются опциональными.

## Реализовано в feature/visibility-quotas

- План экранных положений: 15% center, 65% offset, 15% edge, 5% near_clip.
  Это запланированные положения, а не гарантия фактического отсечения.
- Dagor корректирует направление взгляда без сдвига позиции камеры/танка;
  journal содержит запланированные UV и категорию.
- Экспериментальный режим `capture_visibility_masks` (по умолчанию false).
  Нативный установщик фиксирует LOD на время RGB и изолированного прохода,
  сохраняет действительные параметры финального screenshot, копирует
  reverse-Z глубину сцены до изолированного прохода и вызывает
  `renderIsolated` только для модели танка.
- Сохраняет две бинарные RGB PNG: `raw/masks/amodal/<id>.png` и
  `raw/masks/visible/<id>.png`. Python проверяет размеры, бинарность,
  вложенность видимой маски, подсчёты пикселей и долю видимости.
- В COCO экспериментального режима bbox по видимой непрозрачной части;
  полностью скрытый танк не получает положительной аннотации. Исходный
  приблизительный AABB остаётся в images.jsonl. Сильные перекрытия
  помечены training_eligible=false; весь режим пока diagnostic_only.
- Manifest содержит фактическое распределение измеренной видимости.

## Строгие квоты: первый рабочий вариант

- `enforce_visibility_quotas=true` требует `capture_visibility_masks=true`.
- `count` — целевое число принятых кадров; `visibility_weights` по умолчанию open/light/moderate/heavy = 40/25/25/10. Округление методом наибольших остатков.
- `visibility_candidate_multiplier` (1–20, default 5): общий предел кандидатов, count × multiplier; не размер первого пула. До 1000 кандидатов на карту за один пакет. Один DaEditor на раунд. Все кандидаты проверяются до отбора.
- Строгий отбор одновременно по глобальным квотам видимости и равным целевым количествам по картам (разница не более одного кадра). Целочисленный максимальный поток по матрице карта × видимость допускает разное распределение перекрытий на каждой карте и находит допустимое решение, если оно существует в пуле. При дефиците любой карты или категории публикация запрещена. Отчёт содержит обе квоты и матрицу кандидатов/отбора.
- Видимость <10% исключается из этого режима. При недостатке любой категории старый raw сохраняется, кандидаты и журнал сохраняются, отчёт `runs/<run>/visibility-quotas.json` показывает дефицит. При успехе остаются только выбранные RGB/маски/COCO и метаданные; ID могут иметь пропуски.
- Режим без квот сохраняет диагностическое поведение. Адаптивный поиск перекрытий, ранняя остановка рендера, добор по дефициту и фактическое clipping ещё открыты. Windows-проверка квот необходима.

## Поиск перекрытий по коллизиям (эксперимент)

`search_occlusion=true` требует масок; доступен отдельно от строгих квот.
Для каждой позиции планируется категория open/light/moderate/heavy по весам видимости.
До рендера проверяются все допустимые camera_attempts. 27 точек внутри нейтрального
AABB модели проверяются лучами по рельефу, static collision и RendInst (mesh/tree).
Выбирается кандидат с оценкой видимости, ближайшей к центру запрошенного диапазона.
Если подходящей категории нет, выбирается ближайший допустимый ракурс. При выключении
режима действует прежняя стратегия первого допустимого ракурса.
Коллизии и AABB не эквивалентны силуэту; коллизии могут отсутствовать у части объектов,
а листва/прозрачность и отсечение не измеряются этим методом. Квоты по-прежнему
проверяются исключительно по маскам. Отчёт runs/<run>/occlusion-search.json содержит
попадания в целевые категории и среднюю абсолютную ошибку оценки по ВСЕМ кандидатам.
Windows-проверка C++ и сравнение с обычным режимом обязательны. Перемещение танка
к препятствиям и адаптивный добор ещё не реализованы.


## 2.6.a — многораундовый working refill

- При включённых строгих квотах count задаёт итоговый объём (1–250000);
  без квот сохраняется прежний однопроцессный режим 1–1000.
- Один процесс DaEditor на раунд; следующий запускается после валидации
  предыдущего. Это сознательный промежуточный вариант, не 2.6.b.
- Первый раунд до 2× цели и не больше refill_batch_per_map на карту
  (256 по умолчанию, максимум 1000). Затем план по дефициту и полезным
  остаточным рёбрам потока; при включённом proxy поиск получает веса
  нужных категорий между раундами. Квоты отбора неизменны.
- Единый staging; сквозные ID, новый детерминированный seed на карту/раунд,
  сохранение альтернативных кандидатов, один финальный COCO. Карты
  распределяются ровно (разница не более 1), видимость строго глобально.
- Остановка: точное решение, общий бюджет, refill_stall_rounds (3 раунда
  без прироста выбранного количества), refill_max_rounds (10000).
  Технический сбой — FAILED, не обычная отбраковка. Старый raw не заменяется.
- Журналы в runs/<run>/rounds/round-XXXXX; manifest.json, visibility-quotas.json,
  candidate-pool.jsonl в корне запуска. Обзорные карты в runs/<run>/maps.
  Таймаут в refill ограничен timeout × кандидаты раунда; keep_open несовместим.
- После успеха удаляются невыбранные RGB/маски, после ошибки staging сохраняется.
  Автоматическое возобновление после перезапуска и дедупликация близких сцен
  не реализованы. Пул метаданных находится в памяти, все кандидаты на диске;
  250k — допустимый параметр, не доказанный масштаб.
- Следующий подшаг 2.6.b: один нативный процесс, обратная связь на кадр,
  ранняя остановка внутри пакета. Реальная Windows-проверка после 2.6.b
  по решению пользователя; офлайн-тесты 2.6.a проверяют отдельные сценарии.

## 2.6.b — online feedback (candidate implementation)

Opt-in `visibility_quota_mode=online` with strict quotas (GUI: Online-добор).
One DaEditor process receives immutable BLK tasks and per-frame target decisions.
Python validates the complete RGB/masks/metadata before acknowledging the next
frame; exact map/global visibility quotas remain unchanged. Current map stays
loaded within a task; a scheduler can change maps or stop midway. Native
feedback timeout 300 s; Python timeout per response uses config timeout.
Per-map attempt budget = map target × multiplier; no-gain stop after several
bounded windows; no silent fallback. Technical errors fail closed. Existing
refill mode remains available. Online solves the residual flow on compact map/bin capacities; candidate IDs
are materialized only for explicit selection/export. Large-scale memory/disk
performance and actual native Windows build/run are unverified.
