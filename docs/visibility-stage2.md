# Этап 2: экранная композиция и перекрытия

## Реализовано в feature/visibility-quotas

- Детерминированный план экранных положений на карте и в каждом кадре:
  15% center, 65% offset, 15% edge, 5% near_clip.
- Квоты применяются **к запланированным** кадрам, а не подтверждают фактически
  достигнутую видимость или частичное отсечение.
- После выбора позиции камеры Dagor корректирует направление взгляда на
  `screen_offset_N:p2`, не сдвигая танк или камеру.
- При проверке каждого кандидата пересчитывается bounding box с изменённым
  направлением взгляда. Приемлемость кадра проверяется существующей проекцией.
- В journal записывается `screen_bin_planned` и `screen_offset_uv`. Python
  проверяет соответствие запланированному смещению перед публикацией кадров.
- Добавлены чистая функция расчёта пиксельной видимости по двум reverse-Z
  depth-массивам и тесты. **Её входные depth-массивы ещё не связаны с Dagor.**

## Ещё НЕ реализовано

- Захват в Dagor изолированной глубины модели и сцены на одной камере/LOD;
  native `renderIsolated` ещё не подключён к кадру.
- Сохранение `visible_mask` и `amodal_mask` как PNG/RLE.
- Фактические `bbox_visible`, `visible_fraction`, `frame_fraction` и
  `tile_fraction` по GPU-маскам.
- Квоты по реально подтверждённому перекрытию с повторными попытками до
  достижения целевого количества.
- Отдельная нарезка full RGB на 640/960 с сохранением группы сцен.

Сейчас COCO по-прежнему хранит `approximate_amodal` и **не должен**
использоваться как точная разметка частично перекрытого танка.

## Windows-проверка

1. `git switch feature/visibility-quotas`, `git pull`.
2. Запустить Python тесты `python -m unittest discover -v`.
3. Пересобрать Dagor штатной командой проекта: установщик применяется
   после существующего native patchset, не откатывает локальные файлы.
4. Сгенерировать диагностическую серию 20–100 RGB кадров.
5. Сравнить положения и BLK-поля `screen_bin_planned` и `screen_offset_uv`
   с планом из `runs/run-*/plans/*.json`.
6. Визуально проверить размер, ориентацию и частичное отсечение; только
   после этого считать native-интеграцию подтверждённой.

Запуск Windows DaEditor не выполнен в среде разработки: игровой CDK,
модели и DirectX доступны только на целевой машине.
