# dataset/ — рабочий исходный датасет KolobanovEye 2.0

В каждом пользовательском запуске обрабатывается одна или несколько выбранных карт War Thunder **в одном процессе DaEditor**. Результат всегда хранится внутри проекта. Никаких train/val/test и релизов пока не создаём.

```text
dataset/
├── README.md                       # отслеживается Git
├── raw/                            # один завершённый набор за последний успешный запуск
│   ├── images/                     # все RGB кадры, без разбиения по картам
│   │   ├── 00000001.png
│   │   └── ...
│   ├── annotations/
│   │   └── instances.json          # общий COCO
│   ├── metadata/
│   │   ├── images.jsonl            # метаданные каждого кадра
│   │   ├── scenes.jsonl            # группировка по позициям (без train/test)
│   │   ├── maps.json               # карта, границы танкового квадрата и обзор
│   │   └── generation_config.json
│   └── manifest.json               # run_id, количество кадров/карт, редакторов=1
├── runs/
│   └── run-YYYYMMDDTHHMMSSZ-XXXXXXXX/
│       ├── capture/                # отдельные BLK-задания карт
│       ├── plans/                  # планы камеры и положения танков по картам
│       ├── maps/                   # отдельные обзорные PNG для каждой карты
│       ├── environment/            # общие настройки среды DaEditor
│       ├── journals/               # журналы кадров, могут остаться при ошибке
│       ├── probe.level.blk
│       ├── probe.level.local.blk
│       ├── probe.dcmd              # все карты в одной консольной очереди
│       ├── probe.dcmd.log
│       ├── host-stdout.log
│       ├── generation-config.json
│       └── manifest.json
└── analysis/                       # появляется только после нажатия «Провести анализ»
    ├── index.html
    ├── maps/*-positions.html
    └── report.json
```

В `runs/run-...` **нет** изображений датасета, вложенных `runs/avg_*` и отдельного `coco/`. Подготовка Dagor использует одну общую рабочую папку, а задания карт отличаются только BLK и планами.

## Правила обновления

- Каждый запуск собирает новый `raw` во временной папке `dataset/.raw-staging-...`; старый не затрагивается, пока не завершатся рендер, проверки PNG, чтение journals и сборка COCO.
- При успешном завершении папка `raw` заменяется новой. GUI спрашивает подтверждение; CLI требует `--replace-raw`. При ошибке текущий `raw` остаётся неизменным.
- Результаты прошлых запусков `runs/run-...` **не удаляются автоматически**. Они содержат технические логи и PNG обзорных карт, но не дубликаты RGB.
- `analysis` создаётся отдельным шагом и при повторном запросе пересобирается для текущего `raw`. Его HTML-карты **ссылаются** на PNG в соответствующем `runs/<run-id>/maps`; поэтому не удаляйте этот технический запуск, пока нужны карты анализа.
- Содержимое `dataset/` (кроме `README.md`) игнорируется Git.

## Команды

```powershell
cd D:\Projects\KolobanovEye
python .\ke_gui.py

# Через конфигурацию, без GUI:
python .\ke_generate.py --config .\config.example.json
python .\ke_generate.py --config .\config.example.json --replace-raw

# Отдельный анализ текущего raw:
python -m tools.ke_analysis --dataset .\dataset
```

После анализа откройте `dataset/analysis/index.html`, выберите нужную карту, наведите на точки танков. Позиции берутся из реальных метаданных кадров. Ориентация изображения относительно мировых X/Z пока требует проверки на Windows.

Новая архитектура проверена автоматическими офлайн-тестами; многокартовая последовательная генерация на **реальном Windows/DX11** ещё не подтверждена.
