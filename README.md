# KolobanovEye 2.0

Локальный генератор синтетических RGB-изображений и COCO-аннотаций для детекции танков (`tank`) на ресурсах War Thunder с использованием открытых исходников Dagor Engine, CDK и закреплённого OOZ.

**Состояние 26.11.2026:** завершён переход к единому online-конвейеру diverse + AVF GPU. Предыдущий Windows-прогон: 600/600 кадров на Abandoned Factory, все квоты выполнены. После финальной очистки необходим повторный приёмочный прогон на Windows. [Состояние по ТЗ](docs/project-status.md).

## Как устроена генерация

1. Выберите карты в белом списке, подготовьте анализ объектов для всех выбранных карт и укажите папку кэша.
2. Укажите число кадров, seed, параметры сцены и веса четырёх категорий видимости.
3. Один DaEditor обрабатывает online-задания. Diverse объединяет поиск по препятствиям, проёмам, растительности, рельефу и обратной связи; AVF GPU и полные маски обязательны.
4. Квоты добираются адаптивно. RGB, amodal/visible masks и COCO экспортируются только после проверки полного набора. Технические журналы остаются в dataset/runs.
5. «Провести анализ» отдельно создаёт HTML-отчёт. Накопительный кэш сцен опционален, по умолчанию выключен.

В случае неудачного рендера/валидации прежний `dataset/raw` остаётся неизменным. GUI спрашивает подтверждение перед заменой последнего результата. Историю технических запусков в `dataset/runs` пользователь очищает самостоятельно. Всё `dataset/`, кроме README, исключено из Git.


**Контроль качества:** если рендер пропустил несуществующий слой атласа теней дерева, файлы `raw/metadata/maps.json` и `raw/manifest.json` отмечают `impostor_preshadow_incomplete` и число пропущенных обновлений. Такие карты требуют визуальной проверки и не считаются полностью эквивалентными исходной игре по теням.

## Безопасность сборки OOZ и диагностика

19 ноября 2026 Kaspersky File Antivirus при сборке `ke-ooz-replay.exe` выдал **высокоприоритетное эвристическое обнаружение** `VHO:Trojan.Win32.Agent.gen` (MD5 `B5797152ED80A29AD81E464805F82A84`). До независимой проверки файла нельзя считать срабатывание ложноположительным. **Не восстанавливайте этот EXE из карантина, не отключайте антивирус и не запускайте его.** Обычная команда `kolobanoveye.py build` больше не создаёт `ke-ooz-replay.exe`: автономный C++ инструмент исключён из обязательного пути сборки. Файлы диагностики сохраняются в `dataset/runs/run-.../ooz-failures/` без запуска этого EXE.

Если `avg_abandoned_factory.bin` не загружается, сохранённый локально `failed-ooz.bin` и `failed-ooz.txt` можно исследовать после завершения проверки инструментария. Данные карты не добавлять в Git и не отправлять на публичные сервисы без разрешения правообладателя. Для дальнейшего исследования достаточно сообщить текст `host-stdout.log` и результаты штатных проверок.

**Ни один из этих изменений не требует восстановления файла из карантина.**

## Запуск в Windows Developer PowerShell x64

```powershell
cd D:\Projects\KolobanovEye
git fetch origin
git switch feature/occluder-guided-sampling
git pull --ff-only origin feature/occluder-guided-sampling

python -m unittest discover -v

# OOZ закрепляется один раз, если ещё не перенесён в vendor/ooz
python -m tools.vendor_ooz

# После первоначального закрепления OOZ внешний D:\Projects\ooz не нужен
python .\kolobanoveye.py build --dagor D:\Projects\DagorEngine
python .\ke_gui.py
```

Если ранее был установлен OOZ в `vendor/ooz`, повторное выполнение `python -m tools.vendor_ooz` не требуется. [Подробнее о закреплённом декодере](vendor/README.md).

Запуск без GUI (сначала замените путь `smart_placement_cache` в `config.example.json` на реально подготовленный кэш):

```powershell
python .\ke_generate.py --config .\config.example.json

# Если нужно заменить уже существующий dataset/raw:
python .\ke_generate.py --config .\config.example.json --replace-raw

# Анализ после успешной генерации:
python -m tools.ke_analysis --dataset .\dataset
```

**Обязательно:** `D:\Projects\DagorEngine` должен быть локально собран по закреплённой ревизии `9639942de5a8e5b01d91977f60ed82cda22d5f41`; для DX11 нужен запущенный Windows-сеанс.

## Что в интерфейсе

Три вкладки: «Основное», «Сцена и камера», «Качество». Видимость задаётся весами с предварительным расчётом квот. Поле накопительного кэша показывается только при его включении.

В «Дополнительно» две диагностические галочки: сверка GPU с CPU и ожидание сходимости освещения неба. Также доступны загрузка, сохранение и сброс настроек. Маски, AVF, diverse, online-добор и стабилизация кадра не отключаются. Старые конфиги мигрируют к единому конвейеру. Низкоуровневый одиночный кадр и пакетный анализ объектов остаются инженерными инструментами, не альтернативными генераторами датасета.

## Уже реализовано и ограничения

- Проверена генерация 600 кадров с заданным распределением видимости; COCO bbox вычисляются из валидированных полных масок.
- Сохраняются проверки рельефа, воды, столкновений, стабильности изображения и целостности журналов. Невалидные кадры не участвуют в квотах.
- Нейтральная артикуляция пока обязательна. Погода, улучшенный рендер, дополнительные модели и отрицательные кадры остаются отдельными этапами.
- Разделение на train/val/test не входит в текущий конвейер.
- После очистки требуется Windows-сборка и многокартовая приёмка; накопительный кэш сцен нуждается в отдельном cold/warm тесте.
